# 管理组与全项目授权设计

**日期：** 2026-07-26
**状态：** 已确认，待实现

## 目标

在现有分组授权模型中增加一个系统级“管理组”。管理组始终只包含管理员，并拥有当前及未来所有项目的访问权限。

## 规则

- 管理组使用稳定代码 `admin`，名称为“管理组”，说明其成员由管理员角色自动维护。
- 用户 `is_admin = true` 时必须属于管理组；`is_admin = false` 时不得属于管理组。
- 已存在的管理员和项目在迁移执行时会被回填到正确状态。
- 任意未来新增的项目会自动授予管理组，不需要管理员再到后台逐项开通。
- 用户仍可同时属于默认分组或普通分组；管理组只额外提供全部项目的访问权限。

## 实现边界

通过数据库迁移创建管理组并安装两类 PostgreSQL 触发器：

1. `users.is_admin` 变化时，同步插入或删除对应的 `user_groups` 管理组关系。
2. `projects` 新建时，为管理组插入启用的 `group_project_access` 记录。

迁移将为所有现有项目授予管理组，并为所有现有管理员建立成员关系。插入操作必须幂等，重复迁移或触发器执行不可产生重复关系。

管理组属于系统组：后台可查看其成员和项目覆盖范围，但不能删除、编辑、手动管理成员，或撤销任何项目权限。普通分组与默认分组的现有管理规则保持不变。

应用层在管理员同步逻辑中不重复实现成员或项目授权同步；只更新 `users.is_admin`，将关系一致性留给数据库触发器。

## 验证

- 新迁移按顺序运行，并创建唯一的管理组、完整的现有项目授权和现有管理员成员关系。
- 将用户提升为管理员会自动加入管理组；撤销管理员会自动移出。
- 创建新项目后，管理组自动获得启用的项目授权。
- 管理组不允许通过后台 API 删除、编辑、添加/移除成员、授予或撤销项目权限。
- 管理员通过管理组能从项目目录取得全部已启用项目；非管理员不因管理组获得权限。

## 非目标

- 不新增手动设置或取消管理员角色的后台界面。
- 不改变默认分组的自动加入和智能穿戴项目默认授权。
- 不将普通分组升级为系统组，也不改变它们的权限管理行为。
