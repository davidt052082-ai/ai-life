# 学习计划云端编辑设计

## 背景

本地“学习时间统计”页面新增了编辑学习计划的能力。AI Life 线上版本已经具备账号鉴权、项目授权、人物管理和 PostgreSQL 云端同步，不能用本地 `localStorage` 版本直接覆盖，否则会破坏现有数据模型与跨设备同步。

## 目标

在保留现有登录、项目权限、人物管理和云端同步的前提下，为 `/projects/study-plan` 增加编辑已有学习计划的能力。

## 非目标

- 不引入 `localStorage` 作为计划数据源。
- 不改变现有项目路由、授权规则或项目目录结构。
- 不新增数据库表或迁移。
- 不改变删除计划和人物管理流程。
- 不重构无关页面或 API。

## 交互设计

计划卡片成为可点击、可键盘聚焦的编辑入口。点击卡片或在卡片聚焦时按 Enter/Space，打开现有计划弹窗并填入该计划的全部字段。

编辑状态下：

- 弹窗标题显示“编辑学习计划”。
- 提交按钮显示“保存修改”。
- 人物、科目、地点、开始日期、起止时间、学习天数、休息天数和目标学习天数均可修改。
- 点击卡片内的删除按钮只执行删除，不触发编辑。
- 关闭或取消弹窗时清除编辑状态；下次新增计划仍使用默认值。

保存成功后关闭弹窗并重新读取服务端数据。保存失败时保留弹窗和用户输入，并显示后端返回的错误信息。

## API 与数据流

新增：

`PATCH /api/projects/study-plan/study-plans/:id`

请求体沿用新增计划的完整字段结构。服务端继续使用现有输入验证，并确认所选人物属于当前账号和当前项目。

仓储层通过 `id + user_id + project_id` 限定更新范围，更新所有可编辑字段和 `updated_at`，保留计划的 `id` 与 `created_at`。更新成功返回完整计划；目标不存在时返回 `404 PLAN_NOT_FOUND`。

数据流：

1. 客户端从已加载的云端计划中选择目标。
2. 弹窗预填目标数据。
3. 客户端提交完整计划到 `PATCH /:id`。
4. 路由校验输入、人物归属和项目权限。
5. 仓储层原位更新并返回计划。
6. 客户端重新请求人物与计划列表并渲染。

## 错误处理

- 无效字段：返回 `400 INVALID_INPUT`。
- 人物不属于当前账号或项目：返回 `400 INVALID_INPUT`。
- 计划不存在或不属于当前账号/项目：返回 `404 PLAN_NOT_FOUND`。
- 未登录或无项目权限：沿用现有 `401/403` 行为。
- 数据库异常：沿用统一的 `500 STUDY_PLAN_SAVE_FAILED` 响应。

## 测试

- 路由测试覆盖 `PATCH /:id` 注册、成功更新、人物归属校验和不存在计划。
- 仓储测试覆盖更新 SQL 始终包含 `id`、`user_id`、`project_id` 范围，并保留创建时间。
- 页面测试覆盖编辑入口、编辑标题/按钮，以及客户端使用 `PATCH` 且不包含 `localStorage`。
- 运行现有完整测试，确认登录、项目授权、人物管理、计划新增/删除及其他项目未回归。

## 发布与验证

本次涉及静态页面、客户端脚本、路由与仓储代码，因此部署后需要按实际进程管理方式重启应用。发布前先在服务器生成同目录候选文件并核对大小与 SHA-256；切换前保留时间戳备份。发布后验证：

1. 线上文件哈希与提交版本一致。
2. 应用本机响应正常。
3. 公网 HTTPS 路由保持既有登录与授权行为。
4. 登录后可编辑计划，刷新页面后修改仍从云端读取。

## 成功标准

- 线上登录、授权、人物管理和云端同步保持正常。
- 已有计划可以编辑并保留原计划 ID 与创建时间。
- 页面刷新及跨设备登录后可读取修改结果。
- 完整自动化测试通过，发布验证无哈希或响应异常。
