# 学习计划日期保留设计

## 目标

新增或编辑学习计划后，页面显示的开始日期必须与表单中选择的 `YYYY-MM-DD` 日期完全一致，不因服务器或浏览器时区发生前一天偏移。

## 根因

`study_plans.start_date` 是 PostgreSQL 的无时区 `date` 字段。Node PostgreSQL 驱动可能将其返回为 `Date` 对象；现有仓库用 `toISOString()` 转换该对象，再截取日期。东八区本地午夜在 UTC 中仍是前一天，因此显示日期被减一天。

## 设计

- 学习计划仓库新增无时区日期格式化函数。
- 当数据库值是 `Date` 时，函数使用本地日历字段 `getFullYear()`、`getMonth()`、`getDate()` 组成 `YYYY-MM-DD`，不调用 `toISOString()`。
- 当数据库值已是字符串时，直接保留前十个日期字符。
- 创建和编辑接口继续接收、保存 `YYYY-MM-DD` 文本；学习日循环和前端表单不改变。

## 验证

- 仓库测试模拟 PostgreSQL 返回 UTC 为前一天的 `Date`，断言 API 输出仍为原始本地日历日期。
- 运行完整 `npm test`。

## 自检

- 无未决项或占位符。
- 只修复学习计划日期的序列化边界，不修改数据库字段、历史数据、循环规则或其它项目日期逻辑。
