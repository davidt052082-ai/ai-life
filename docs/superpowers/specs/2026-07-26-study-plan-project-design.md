# 学习计划日历项目设计

**日期：** 2026-07-26
**状态：** 已确认，待实现

## 目标

将已完成的“学习小屋”学习计划日历纳入 AI Life，作为一个受项目分组授权控制的独立项目。登录用户可在手机和电脑间查看并维护同一套学习计划。

## 范围

### 新项目与访问控制

- 新增项目目录项：名称“学习计划日历”，项目代码 `study-plan`，页面路由 `/projects/study-plan`。
- 项目不加入默认分组，也不自动授权给新用户。
- 仅管理员在现有后台向指定分组开启项目权限后，分组成员才可在项目首页看到并进入项目。
- 沿用现有认证、项目目录、分组授权和项目访问中间件；不改变智能穿戴项目的默认授权逻辑。

### 学习计划

每一条计划作为源规则保存，并只属于“当前登录用户 + 学习计划项目”：

- 学习者：大公主或小公主。
- 课程信息：科目、地点、开始日期、开始时间、结束时间。
- 循环规则：连续学习天数、连续休息天数、目标学习天数。
- 审计字段：计划 ID、创建时间、更新时间。

课程日不单独持久化。前端在展示时按规则生成学习日：从开始日期起依次排入学习日，经过休息日后继续循环，直到达到目标学习天数。同一日可由多个计划生成多个课程，并按开始时间排序。

### 界面与交互

- 延续已确认的“学习小屋”视觉与移动端自适应布局。
- 顶部视图为总览、大公主、小公主和日历；日历可前后切换月份。
- 总览显示当月两人的学习日、课程数和课程时长；个人视图只显示对应学习者的计划和课程。
- 新增计划表单校验必填字段、时间顺序和循环天数；学习天数及目标学习天数必须至少为 1，休息天数可为 0。
- 日历中使用两种颜色区分学习者，显示灰色休息日提示；计划完成后不得继续显示休息日。
- 用户可删除整条计划；删除前确认，确认后计划及生成课程立即消失。

## 数据与 API

新增一张 `study_plans` 表，以 `user_id`、`project_id` 与计划 ID 共同限定数据范围，并外键关联既有用户与项目记录。为 `(user_id, project_id, updated_at)` 建索引，用于按账号加载计划。

在 `/api/projects/:code/study-plans` 下提供受登录和项目授权保护的接口：

- `GET /`：返回当前用户在当前项目的全部计划。
- `POST /`：校验并创建计划。
- `DELETE /:id`：只删除当前用户、当前项目下的指定计划；不存在时返回 404。

路由必须拒绝不匹配 `study-plan` 的项目代码，避免接口被错误用于其他项目。前端加载时读取 API；新增和删除成功后以服务端返回的数据刷新视图。网络或保存失败时保留当前已加载画面并显示可理解的错误提示，不能将失败操作表示为已同步。

## 迁移与项目种子数据

新增数据库迁移：

1. 创建 `study_plans` 及索引。
2. 向 `projects` 插入 `study-plan` 项目（使用稳定 UUID、名称、说明、路由和排序）。迁移需可重复执行。
3. 不向默认分组插入学习计划项目的授权；管理员通过既有后台手动授予。

不迁移早期独立 HTML 的 `localStorage` 数据。本次没有可安全关联到 AI Life 登录账号的本地数据来源；用户可在新项目中重新录入计划。

## 验证

- 数据库迁移包含学习计划表与未默认授权的项目记录。
- 未获分组授权的用户看不到项目、不能进入页面、不能调用计划 API。
- 获授权用户只能读取和修改自己的计划，且项目范围被正确限制。
- 计划生成覆盖“学习 5 天、休息 1 天、目标 18 天”、休息天数为 0、同日多计划排序和计划结束边界。
- 表单拒绝无效日期、时间和循环参数；删除需确认且数据同步更新。
- 在窄屏浏览器中日历与表单可正常操作。

## 非目标

- 不实现单日改期、暂停或覆盖规则。
- 不实现课程实际打卡、学习时长记录或提醒通知。
- 不实现不同账号共享或协作编辑同一计划。
