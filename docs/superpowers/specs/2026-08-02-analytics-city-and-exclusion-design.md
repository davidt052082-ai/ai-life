# 运营统计城市维度与自身流量排除设计

## 目标

1. 在运营控制台按城市展示访问数据。
2. 不记录本机开发、部署健康检查或已配置内部网段产生的统计事件。
3. 继续不保存原始 IP，也不调用第三方 IP 地理定位服务。

## 数据与可信边界

新增迁移 `009_analytics_city_and_exclusion.sql`，在 `analytics_events` 增加可空 `city_name`，并为 `event_date + city_name` 增加部分索引。城市仅在 `TRUST_PROXY=true` 时由服务端读取 `CF-IPCity`，其次读取 `X-Geo-City`；值会去除空白、截断至 80 字符，缺失时保持为空。

客户端不能提交城市、国家、IP 或任何内部流量标识。应用仍仅存储可选的不可逆 `ip_hash`，不保存原始 IP。已有事件因没有原始 IP，无法补充城市，运营界面将其归入“未知城市”。

## 自身流量排除

公开事件上报在限流和写库前检查请求 IP。以下地址默认不写入 `analytics_events`：IPv4/IPv6 回环地址、IPv4 私有网段（`10/8`、`172.16/12`、`192.168/16`）和 IPv6 ULA（`fc00::/7`）。

新增可选环境变量 `ANALYTICS_EXCLUDED_IPS`，使用逗号分隔 IP 或 CIDR，例如：

```dotenv
ANALYTICS_EXCLUDED_IPS=203.0.113.12,198.51.100.0/24
```

该配置用于部署服务器出口、办公网或内部监控地址。匹配的请求直接返回 `204`，不创建统计事件，不影响网页功能。服务端业务事件不使用请求 IP，因此不受此规则影响。

## 控制台与 API

`GET /api/admin/analytics/breakdown` 增加 `dimension=city`。其返回值为前 20 个城市及访问数量；空值标准化为“未知城市”。运营控制台将“国家/地区”卡片替换为“城市”，其余视图和日期范围不变。

日汇总新增 `city` 维度的页面浏览指标。原始事件仍是 90 天运营查询的准确来源，日汇总用于长期保留。

## 测试与验收

1. `TRUST_PROXY=false` 时即使请求含城市头，城市仍为空。
2. `TRUST_PROXY=true` 时，`CF-IPCity` 优先于 `X-Geo-City`，并被安全规范化。
3. 默认回环/私有地址和 `ANALYTICS_EXCLUDED_IPS` 命中的 IP 返回 `204` 且不调用仓储写入。
4. 城市维度查询使用 `city_name`，空值显示“未知城市”。
5. 控制台显示“城市”而不再显示“国家/地区”。
6. 现有统计、权限和全量测试继续通过。
