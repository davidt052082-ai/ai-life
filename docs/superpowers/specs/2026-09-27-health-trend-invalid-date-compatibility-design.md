# 健康趋势无效日期兼容修复设计

## 背景

“减肥打卡”的趋势接口需要读取完整历史事件，再在应用层计算近 28 天汇总。线上验收发现，部分旧事件缺少有效的 `planDate`。这些记录进入“执行与行为”的全部历史趋势后，会触发浏览器 `RangeError: Invalid time value`，导致详情图无法显示。

## 目标

- 保留完整历史接口改进，修复近 28 天统计漏项问题。
- “执行与行为 → 全部历史”遇到无效日期记录时不报错。
- 不修改、不补写、不删除数据库中的既有健康数据。
- 不影响体重、腰围等身体指标趋势。

## 方案

在前端趋势数据聚合边界校验事件和餐食日期：

1. 将 `planDate` 规范化为 `YYYY-MM-DD`。
2. 只有严格匹配且能表示真实日历日期的值才进入趋势聚合。
3. 缺失、格式错误或不存在的日期记录仅从趋势图中忽略，原始记录继续保留在数据库和接口历史数据中。
4. 后端继续返回完整历史，让其他功能可以按需处理这些记录。

选择前端容错而不是清洗数据库，是为了让发布保持可逆且不改变用户数据。后端不主动丢弃历史记录，也便于后续诊断数据来源。

## 代码范围

- `health-client.js`：增加日期规范化/校验，并在执行趋势聚合前过滤无效日期。
- `src/routes/healthRoutes.js`：保留已完成的完整历史读取与近 28 天应用层过滤。
- `test/health-page.test.js`：验证前端包含无效日期防护。
- `test/health-routes.test.js`：保留完整历史与近 28 天汇总的接口回归测试。

## 错误处理

- 无效日期不产生图表点，也不阻断其余有效历史记录。
- 不向用户显示技术错误；若过滤后没有有效记录，沿用“暂无记录”状态。
- 发布验收若仍出现浏览器错误，立即恢复更新前备份。

## 测试与发布

1. 增加无效、缺失日期与有效日期混合输入的前端回归断言。
2. 运行健康模块测试和完整测试套件。
3. 仅提交本次相关文件。
4. 记录本地文件大小和 SHA-256，上传候选包后复核。
5. 在服务器保留时间戳备份，以同目录暂存文件原子替换。
6. 因路由代码变化，重启实际 PM2 进程。
7. 验证线上文件哈希、应用本地响应、公网页面，以及“总饮水量 → 全部历史”无浏览器错误。

## 成功标准

- 完整测试无失败（允许既有的独立数据库集成测试跳过）。
- 公网页面返回成功并保持登录及健康数据不变。
- 体重全部历史和执行类全部历史均能打开。
- 浏览器控制台无 `Invalid time value` 或其他新增错误。
